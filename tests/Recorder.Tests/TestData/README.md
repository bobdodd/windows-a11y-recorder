# Test data

`android-screen-sample.h264` is an H.264 stream the size of the Pixel 10 Pro XL's screen, 1080 by 2404, in the High profile, limited range, BT.709, as the phone's own stream is (docs/validation/android-recording-plan.md, results of part 3, step 3a). It is made with FFmpeg and holds no picture from a phone: six pictures of one colour (sRGB C03020), then six of another (sRGB 2060A0), at 30 a second, with no B-frames.

```
ffmpeg -f lavfi -i "color=c=0xC03020:s=1080x2404:r=30:d=0.2" -f lavfi -i "color=c=0x2060A0:s=1080x2404:r=30:d=0.2" -filter_complex "[0][1]concat=n=2:v=1,scale=out_color_matrix=bt709:out_range=tv,format=yuv420p" -c:v libx264 -profile:v high -preset veryfast -bf 0 -g 60 -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv -x264-params "aud=1" android-screen-sample.h264
```

`android-screen-sample.lengths` gives each access unit's length in bytes, one a line, from `ffprobe -show_packets -show_entries packet=size -of csv=p=0`. The first holds the parameter sets with the key frame.

`android-touch-check4.txt` is what `getevent -lt` printed for the Pixel 10 Pro XL's touch screen in feasibility check 4, on 2026-11-07: three taps, near the top, in the middle and near the bottom of the screen, with TalkBack on (docs/validation/android-feasibility-plan.md). It holds only the touch screen's events and their times. The file the check's script saved begins with a byte order mark, from PowerShell's `Set-Content -Encoding UTF8`, and has a blank line after each line and Windows line ends; those are removed here, and nothing else is changed. The check did not save the axis ranges `getevent -lp` gave, so the tests use x 0 to 13439 and y 0 to 29919, ranges that turn the three taps, rounded to the nearest pixel as the script rounded them, into the positions the check reported (x 603, y 171; x 654, y 1188; x 613, y 2155). They were chosen before the phone's own ranges were known; test 43 of the Android recording validation plan later read them from a recording of the Pixel, on 2026-11-10, as x 0 to 13439 and y 0 to 29919, the same.

`android-talkback-check3.txt` is the TalkBack lines `adb logcat -v monotonic` printed for TalkBack's process on the Pixel 10 Pro XL in feasibility check 3, on 2026-11-07: TalkBack 17.1 at log output level Verbose, with three swipes on the home screen (docs/validation/android-feasibility-plan.md). It holds the 1,189 lines with the tag `talkback`, unchanged; the check's file, of 1,196 lines, also held five lines of other tags from the same process and two lines logcat printed itself, "dmesg: klogctl: Permission denied" and "--------- beginning of main", which are left out. The file the check's script saved begins with a byte order mark and has Windows line ends; those are removed here. Its times have three decimals, as the check did not ask for `-v usec`. The lines show what was on the phone's screen; the owner said on 2026-11-10 that the phone holds nothing that needs to be hidden.
